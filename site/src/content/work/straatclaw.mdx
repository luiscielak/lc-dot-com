overview: "Most AI tools are a clever assistant in a box. You ask, copy the answer somewhere else, and start over next time. I wanted something different: agents that hold context for weeks, do small jobs on a schedule, and know exactly what they’re allowed to do without asking me.\n\nSince May I have run a small team of named agents on a Mac mini at home, on top of Hermes Agent. Five months later, it runs every day. I didn’t build Hermes. It’s Nous Research’s open-source framework. Hermes gives me the plumbing: tools, local files, memory, scheduled jobs, skills, a task queue, and a gateway to chat apps. What I designed is everything people actually experience: who does what, what each agent may do alone, when it has to stop and ask, and how that ask shows up on my phone.\n\nThe core question turned out to be a product design question, not a model question: when will someone let an agent act for them?"
challenges:
  - title: "Predictable"
    body: "I should know what each agent will and won’t do before it acts."
  - title: "Interruptible"
    body: "Anything with consequences outside my own notes should wait for me."
  - title: "Easy to approve"
    body: "The ask should come to me where I already am, and be quick to answer."
  - title: "Inspectable"
    body: "I should be able to read what an agent “knows” and fix it."
solution: "Instead of one giant agent, I designed a small organization. Every agent gets a short profile: what it does, what it’s not responsible for, what it reads, what it writes, and when it hands off to me.\n\n- StraatBot, the orchestrator and chief-of-staff layer. It captures, triages, routes work, tracks open loops, and escalates to me.\n- Scout, research. Morning briefs, signals, watchlists, and a weekly synthesis.\n- Finley, finance. Cash flow, budget tracking, and the numbers behind decisions. Finley works from a private data inbox only it reads; other agents get a status or a flag, never raw figures.\n- Helpers by role for household operations, food and groceries, and travel planning.\n- A product design squad that runs a staged flow: PRD, lo-fi wireframes, mid-fi specs, a design kit, then a runnable prototype, based on my public Cursor rules.\n\nScout writes a calm brief every morning: the day setup, a Philly pulse, a few AI and product signals, one thing to watch, and a short bottom line. It cites its sources. If a section has nothing worth saying, it writes “No strong signal today” instead of padding. It also makes a short narrated audio version. It only saves a signal as its own note if it might matter next week. On Fridays it reads the week’s briefs and signals, writes a weekly synthesis, and sends me a short summary. That is the difference between a headline bot and a signal agent.\n\nThe design squad is six roles, each a command: /new-project, /prd, /lofi, /midfi, /ui-proto, /hifi. I ran the whole pipeline on a brief for the cockpit itself. The pipeline designed its own control panel. PRD and lo-fi were good. New project, mid-fi, and hi-fi were okay. The prototype was weak. The rules assumed shadcn’s rounded corners, shadows, and gradients. My design system, Konstrukt, is square corners, no shadows, one palette. The two kept fighting. I could have cleaned up the output by hand. That fixes one run. So I’m fixing the rules instead. I reran only the prototype step. It went from weak to okay. Fix the rules, not the output.\n\nHermes exposes capabilities; permissions are granted to named agents that run on Hermes."
research: "There was no formal research study. This section is why the design exists.\n\nWhen one agent can read everything, write anywhere, and act on my behalf, I can’t predict it — so I can’t trust it. Teams hit the same wall when they bring agents into real work: a traveler handing off a trip, a team letting an agent touch shared tickets, a developer letting an agent change infrastructure.\n\nThe brief I set: predictable, interruptible, easy to approve, inspectable."
decisions: "The most useful thing I wrote wasn’t a prompt. It was a permission matrix: six levels that spell out what an agent can do alone and what it has to bring back.\n\n| Level | What the agent can do | Example |\n| --- | --- | --- |\n| L0 Observe | Read only | Read notes and sources |\n| L1 Draft | Write something for my review | A brief, a draft reply |\n| L2 Internal write | Change internal notes and task lists | Save a signal note, move a task |\n| L3 Reversible | Run operations that can be undone | Run a local script |\n| L4 External, with approval | Act outside the system, only after I say yes | Send an email, publish a post, submit a form |\n| L5 Manual only | Never done by an agent | Payments, contracts, destructive deletes, credential changes |\n\nEvery agent has a default level. Scout can write reports but never contacts anyone. StraatBot can open a bug issue and hand off a fix, but it can’t publish. Finley works from a private inbox and never shares raw numbers. One rule sits above all of it: human judgment gates external action.\n\nThis did more for my trust in the system than any model upgrade. When I know what an agent cannot do, I am comfortable letting it do the rest.\n\nApprovals arrive in chat, not in a dashboard. Telegram is for quick captures, status, approvals, and the morning brief. Slack is for real work, one thread per task.\n\nHermes Agent has a built-in approval gate for risky commands. I configured when it fires and where it reaches me. I did not invent the prompt. When an agent tries something like that, I get Allow Once, Allow Session, Always Allow, or Deny in Slack. If I do not answer, nothing runs. I lean on that a lot.\n\nA bug, from screenshot to fix. If I spot a layout bug on my site, I send StraatBot a screenshot. It opens an issue in Linear with the evidence, the expected and actual behavior, and acceptance criteria. When the issue is clear, it hands a scoped prompt to Cursor’s CLI agent: fix only this bug, avoid unrelated refactors, run the checks, and report what changed. Nothing closes until the fix is retested and verified. A tight spec, a bounded worker, and a review gate."
outcome: "StraatClaw is in daily personal use. It is not a shipped company product, and this page claims no usage metrics.\n\nI organize Cursor Philly on top of a day job and a few side projects. So I gave the agents the repetitive parts. Four jobs, all running on Hermes:\n\n1. RSVP check-ins. Scout checks the Luma page and tells me the count. 111 on Tuesday, 130 on Thursday.\n2. Event-week reminders. StraatBot keeps the week in order: the announcement, the reminder, the night itself.\n3. The morning pulse. Scout’s brief has a Philly section. If there’s nothing worth saying, it says “no strong signal today” instead of padding.\n4. Setup and logistics. A day-of checklist, so I’m not holding it in my head.\n\nWhat they don’t do: they don’t post for me, and they don’t talk to guests. I send and say everything people see.\n\nThe screens below are mockups of a chat thread. The last two use placeholder content. The RSVP and reminder screens use real dates and counts."
reflection: "Memory lives in plain notes. My source of truth is an Obsidian vault in plain Markdown. The agents write to it, and the vault syncs to a private GitHub repo on its own, several times a day.\n\nIn September I audited it. The built-in memory files were full, so new writes failed. The external memory provider was injecting too much context. Two other plugins had never stored a thing. The lesson: give every fact one home, and compare tools with a real test, not a vibe.\n\nI’m not trying to remove anyone’s judgment, including my own. I’m trying to give it better context and a little more leverage. The idea fits in one line: I don’t want one giant agent. I want a small organization of bounded agents.\n\nWhat I learned about trust:\n\n- Trust comes from limits, not intelligence.\n- The approval moment is the product.\n- Silence has to mean no.\n- Honest output builds more trust than impressive output.\n- Memory needs an owner and a home.\n\nWhat I would tell you to try: start with one annoying workflow. Write down what done looks like. Give one agent a narrow role and a name. Add a review step before anything high stakes. Give each task its own thread. Add a schedule only once you trust it.\n\nWhat’s next: StraatClaw Deploys is planned as a way to put a prototype online without handing an agent the keys to everything — a grant broker on the Mac mini, scoped expiring access, and approvals through a separate Telegram bot. That build is in progress; this section will be updated once it exists."
