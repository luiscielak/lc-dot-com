tldr: "They run on a Mac mini at home, on Hermes Agent, the open-source framework from Nous Research. I didn’t build Hermes. I built the team: who does what, what each agent can do on its own, and when it has to stop and ask me."

overview: "Every morning, an agent named Scout writes me a calm brief. It cites its sources. If a section has nothing worth saying, it writes “No strong signal today” instead of padding.\n\nScout is one of a small team of AI agents. Each one has a name, a job, and limits. StraatBot, my chief of staff, is the single front door. I can drop a thought or a task on it without deciding who should do it, and it either handles it or routes it to the right lane.\n\nI could have built one master agent that holds everything. I didn’t want that. When one agent can read everything, write anywhere, and act for me, I can’t predict it, and the risk of context leaking across streams is too high. Separation isn’t overhead. It’s what makes the trust possible."

challenges:

researchHeading: "Version one, from scratch"
research: "I started in May by building it myself. Python, FastAPI, Anthropic, and SQLite, behind a Cloudflare Tunnel. No VPS, no third-party orchestrator, no cloud database. Each agent was a FastAPI route, a `soul.md` system prompt, and its own conversation memory. The soul is the contract.\n\nThe finance agent got its own data volume. StraatBot only ever saw GREEN, YELLOW, or RED summaries, never raw figures. Data isolation was there from day one.\n\nToday the team runs on Hermes Agent instead.\n\nThe reason for building it didn’t change: agents shaped to my life, not the average user’s. Different voices for different domains. Boundaries I control."

solution: "Hermes is the plumbing: tools, memory, scheduled jobs, skills, and a gateway to chat apps. It exposes capabilities. The permissions belong to the named agents that run on it.\n\n- **StraatBot**, orchestrator and chief of staff. It captures, triages, routes work, tracks open loops, and escalates to me.\n- **Scout**, research. Morning briefs, signals, watchlists, and a weekly synthesis on Fridays.\n- **Finley**, finance. Works from a private inbox. Other agents get a status or a flag, never raw numbers.\n- **Helpers** for household, food, and travel.\n- **A product design squad** that goes from PRD to prototype, based on my public [Cursor rules](https://github.com/luiscielak/ai-product-design-rules).\n\nEvery agent has a short profile: what it does, what it isn’t responsible for, what it reads, what it writes, and when it hands off to me. Smaller roles are easier to trust. Same as people."

decisions: "The most useful thing I wrote wasn’t a prompt. It was a permission matrix: six levels that spell out what an agent can do alone and what it has to bring back to me.\n\n| Level | What the agent can do | Example |\n| --- | --- | --- |\n| L0 Observe | Read only | Read notes and sources |\n| L1 Draft | Write something for my review | A brief, a draft reply |\n| L2 Internal write | Change internal notes and task lists | Save a signal note, move a task |\n| L3 Reversible | Run operations that can be undone | Run a local script |\n| L4 External, with approval | Act outside the system, only after I say yes | Send an email, publish a post, submit a form |\n| L5 Manual only | Never done by an agent | Payments, contracts, destructive deletes, credential changes |\n\nEvery agent gets a default level. Scout writes briefs and reports, and never contacts anyone. StraatBot can hand a scoped fix to a coding agent, but it can’t publish. One rule sits above all of it: human judgment gates external action.\n\nThis did more for my trust than any model upgrade. When I know what an agent can’t do, I’m comfortable letting it do the rest.\n\n### The approval moment\n\nHermes has a built-in approval gate for risky commands. When an agent tries one, I get the prompt in chat: the exact command, the rule it tripped, and how far my yes goes. If I don’t answer, nothing runs. My part is the levels and rules that decide when it fires and where it reaches me.\n\n### Two surfaces, on purpose\n\nSlack is threaded. Each piece of work gets its own thread, so the context stays attached to it, and I can watch agents hand off to each other in-thread instead of having it vanish. Telegram I keep the opposite on purpose. It’s my interrupt channel, phone-native, for things that need an answer in a few minutes. Threads give me structure. The app I open gives me urgency."

outcome: "### Scout’s morning brief\n\nScout is the one I rely on most. The day setup, a Philly pulse, a few AI and product signals, one thing to watch, and a short bottom line. It saves a signal as its own note only if it might matter next week. That’s the difference between a headline bot and a signal agent.\n\n### Running Cursor Philly\n\nI organize Cursor Philly on top of a day job and a few side projects, so the agents take the repetitive parts: RSVP check-ins from Luma, event-week reminders, a Philly section in the morning brief, and a day-of checklist. What they don’t do: they don’t post for me, and they don’t talk to guests. I send and say everything people see.\n\n### A bug, from screenshot to fix\n\nIf I spot a layout bug on my site, I send StraatBot a screenshot. It opens a Linear issue with the evidence, expected and actual behavior, and acceptance criteria. Then it hands Cursor’s CLI agent a scoped prompt: fix only this bug, avoid unrelated refactors, run the checks, and report what changed. Nothing closes until the fix is retested and verified. A tight spec, a bounded worker, and a review gate.\n\n### The design squad\n\nMy Cursor rules for AI product design are six steps, each a role with a command, from `/new-project` to `/hifi`. I also had a Design Ops Cockpit meant to run that pipeline. It was a click-through mockup. So I ran the whole pipeline on a brief for the cockpit itself. PRD and lo-fi came out good; the prototype came out weak. Most of the trouble had one cause: the rules assumed shadcn’s rounded corners and shadows, and Konstrukt is square, flat, and one palette. I could have cleaned up one run by hand. I fixed the rules instead, and the rerun took the prototype from weak to okay.\n\n### Memory lives in plain notes\n\nThe source of truth is an Obsidian vault in plain Markdown. The agents write to it, and it syncs to a private GitHub repo several times a day."

reflection: "I’m not trying to remove anyone’s judgment, including my own. I’m trying to give it better context and a little more leverage. I don’t want one giant agent. I want a small organization of bounded agents.\n\nWhat I learned about trust:\n\n- Trust comes from limits, not intelligence.\n- The approval moment is the product.\n- Silence has to mean no.\n- Honest output builds more trust than impressive output.\n- Memory needs an owner and a home.\n\nIf you want to try this: start with one annoying workflow. Write down what done looks like. Give one agent a narrow role and a name. Add a review step before anything high stakes. Give each task its own thread. Add a schedule only once you trust it."
